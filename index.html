개인 기여 · 주행 환경 구성 → 위치 보정·정렬

  • 3대의 독립 Nav2 환경 구성TurtleBot3별 namespace·TF 접두사·Nav2 파라미터와 센서·명령 브리지를 분리했습니다. AMCL 초기 위치와 cmd_vel 전달 흐름을 정리해 RViz 목표 주행을 확인했습니다.
  • Nav2 주행 문제 추적lifecycle inactive 상태와 지도상 장애물에 걸린 시작 위치를 확인해 목표 주행이 멈추는 원인을 분리했습니다.
  • Action 기반 라이다·ArUco 정렬·보정Action 요청 시 카메라를 실행하고, 라이다 벽 직선과 ArUco 마커 방향각으로 방향·좌우·거리를 보정합니다. 정렬 완료 측정값으로 map→base_footprint 위치를 계산해 /initialpose로 발행하고, AMCL/Nav2 위치를 보정한 뒤 카메라를 종료합니다.
  • CPU 부하 대응Action 요청 시에만 카메라를 실행·종료하고, 320×240 캘리브레이션 적용과 TF listener 실행 분리로 부하를 줄였습니다.

02 / ON-DEVICE AI · SAFE EYE

산업 현장 보호구 착용 감지

객체 탐지(OD)와 다중 라벨 분류(MLC)를 비교할 데이터를 구성하고, 비교 결과를 실제 판정 흐름에 반영했습니다.

담당 · 데이터 전처리 / 시스템 통합 / 대시보드

  • 탐지용 데이터를 사람 단위 분류 데이터로 변환약 22,000장의 원본에서 사람 검출·크롭과 PPE 라벨 매칭을 자동화하고, 겹침·저해상도·라벨 충돌 데이터를 제거했습니다.
  • 클래스 불균형과 평가 데이터 누수 대응소수 상태는 모두 유지하고 다수 상태는 최대 1,000장으로 샘플링했습니다. 독립 평가용 원본 100장의 파생 크롭은 학습에서 격리했습니다.
  • 하이브리드 PPE 판정1명은 MobileNetV3 분류(MLC), 2명 이상은 YOLO 객체 탐지(OD)로 분기합니다. 사람 수만큼 반복되는 분류 추론의 속도 저하를 고려했습니다.
  • 대시보드와 모듈 통합config·camera·detector를 분리해 팀원 모델을 같은 입출력 흐름으로 연결하고, 감지 인원·위반·위험 구역·FPS를 한 화면에 표시했습니다.

03 / STM32 · EMBEDDED CONTROL

센서와 상태 표시를 연결한 RC카

STM32F411RE 기반 무선 RC카 팀 프로젝트에서 IMU·초음파 센서와 LCD 상태 표시를 담당하고, 팀의 무선 조종·모터 제어 파이프라인에 통합했습니다.

담당 · 센서 입력 / 장애물 감지 / LCD 상태 표시

  • 초음파 장애물 감지HC-SR04의 Echo 펄스를 타이머 Input Capture로 측정했습니다. 10 cm 이내 장애물을 감지하면 전진 목표 RPM을 0으로 제한하고 후진·회전은 허용했습니다.
  • IMU 기울기 입력ADXL345의 가속도 값을 I2C로 읽어 차체 기울기를 감지했습니다.
  • IMU 기반 LCD 화면 전환IMU로 감지한 기울기 상태에 따라 LCD 화면이 바뀌도록 구현해, 차체 상태를 화면으로 바로 확인할 수 있게 했습니다.
  • 센서·모터 결합 후 오동작 해결기존 코드와 비교하고 개별 동작을 확인한 뒤 납땜·연결 오류를 수정했습니다. 통신 응답뿐 아니라 실제 센서값·출력 동작과 물리적 배선을 함께 검토해야 한다는 점을 배웠습니다.
